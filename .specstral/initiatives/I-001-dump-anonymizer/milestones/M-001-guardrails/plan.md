## Approach

The milestone adds only project scaffolding and one placeholder binary: `go.mod`, `cmd/wanonymizer/main.go`, `Makefile`, `.golangci.yml`, `.goreleaser.yaml`, `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `.github/dependabot.yml`, the zizmor config, `LICENSE`, `README.md`, `.gitattributes`, and the `/bin/` and `/dist/` lines in `.gitignore`. The major choices are the `D-##` rows of `spec.md`; this section gives the shape and the smaller choices.

- Placeholder entry point: `cmd/wanonymizer/main.go` writes one line, `wanonymizer <version>`, to stdout and exits 0, whatever its arguments. The version comes from GoReleaser's `-X main.version={{.Version}}`, else from the build info (a `go install` build carries its module version), else `devel`. Why: the release path needs a binary to build and run, and the CLI rule belongs to M-002 (`architecture.md`). The smoke checks call `wanonymizer --version`; M-002 replaces the placeholder and updates those checks when its CLI rule names another version command.
- `make check` runs, fast to slow, and stops at the first failure: `gofmt -l .` (fails when it prints a path), `go vet ./...`, `golangci-lint run`, `go mod tidy -diff` (Go 1.23 and later: exits non-zero on drift, changes nothing), `go test -race ./...`, `go build ./...`, and the dependency check. Why: it holds each Definition of Done step of `constitution.md`, plus two cheap offline checks; CI runs the same target, so local and CI checks cannot drift.
- Dependency check (D-08): `go list -deps ./cmd/wanonymizer` compared with the deny list, in a small script that the Makefile calls; it prints each denied package it finds. It reads the shipped binary's graph without `-test`, so test code may use `os/exec` and `net`: the golden-dump tests of later milestones run the real entry point.
- Tool versions: each dev tool has one pinned version, checked against its releases page at build time (`build-rules.md`). On 2026-11-27: golangci-lint v2.15.0 (Go 1.27 support since v2.13.0), GoReleaser v2.20.3, actionlint v1.7.12, zizmor v1.33.1, govulncheck v1.10.0. `make tools` installs golangci-lint, GoReleaser, actionlint, and zizmor binaries into `./bin/` (gitignored), and the Makefile prefers `./bin/` over the PATH. CI installs the same versions before it runs `make check`. Why: golangci-lint's docs recommend the binary install and warn against `go install` and `go tool` (golangci-lint.run/docs/welcome/install/local, read 2026-11-27), and dev tools stay out of the module's `go.mod`. Dependabot updates the action SHAs, not these versions: they change by hand.
- Lint config (D-10): `.golangci.yml` with `version: "2"`, `linters.default: standard`, the five added linters, nolintlint with `require-explanation` and `require-specific`, and forbidigo patterns for `fmt.Print*`, `print`, and `println`. Code writes to stdout only through an explicit writer, so a stray print cannot land in the output dump.
- CI (`ci.yml`, D-07): triggers on `push` and `pull_request`; top-level `permissions: contents: read`; checkout with `persist-credentials: false`; `actions/setup-go` with `go-version-file: go.mod`, because the runners' default Go is 1.26.11 (actions/runner-images, Windows 2025 readme, 2026-11-16). A concurrency group cancels superseded runs. Jobs:
  - `check` (Linux): the pinned golangci-lint, then `make check`.
  - `test` (macOS and Windows): `go test -race ./...` and `go build ./...` called directly, because `windows-latest` has no `make` on its PATH. Race needs cgo; the Windows image ships gcc 15.2.
  - `vuln`: govulncheck on `./...`. It queries vuln.go.dev from CI; the tool itself stays offline.
  - `workflows`: actionlint and zizmor (offline, no token) on `.github/workflows/**`, with a zizmor config that sets a hash-pin policy for every action (D-09).
  - `release-dry-run` (Linux): `goreleaser check`, `goreleaser release --snapshot --clean`, `sha256sum --check dist/checksums.txt`, then the amd64 .deb installed with `dpkg -i` in an official Debian image and the amd64 .rpm installed in an official Fedora image, each followed by `wanonymizer --version`. The arm64 packages are built and checksummed, not installed: no arm64 container runs on the x64 runner.
- Release (`release.yml`, D-06): triggers only on `push` of `v*` tags. One job, the only one with `contents: write`, `id-token: write`, and `attestations: write` (and `artifact-metadata: write` when `actions/attest` asks for it). Checkout with full history (GoReleaser's changelog), setup-go, goreleaser-action `release --clean` with `GITHUB_TOKEN` and the tap token secret `HOMEBREW_TAP_TOKEN`, then `actions/attest` (v4; `actions/attest-build-provenance` is now only a wrapper of it) with `subject-checksums: ./dist/checksums.txt`. Why: GoReleaser's attestation guide (goreleaser.com/customization/attestations, updated 2026-08-30). The tap token is a fine-grained token with contents read-write on the tap repository only; the roadmap manual action covers it. The first run is the `release` command's tag push, a live write that waits for the user's yes.
- GoReleaser (`.goreleaser.yaml`, `version: 2`): one build of `./cmd/wanonymizer` with `CGO_ENABLED=0`, `-trimpath`, and the version ldflag, for the 6 targets of D-03; `mod_timestamp` from the commit, so equal inputs give equal binaries. Archives: tar.gz, zip on Windows, each with LICENSE and README. `checksum.name_template: checksums.txt` (SHA-256). `nfpms`: deb and rpm, license MIT, the maintainer of D-02, homepage, description. `homebrew_casks`: the `stefanoginella/homebrew-tap` repository with `HOMEBREW_TAP_TOKEN`, and a post-install step inside `on_macos` that runs `xattr -dr com.apple.quarantine` on the binary (D-05). A snapshot writes the cask to `dist/homebrew/Casks/` and uploads nothing. Homebrew on Linux has run casks with Linux binaries since 4.5.0 (brew.sh, 2025-04-29), but this is not tested here: Linux users have the packages and `go install`.
- `go install` check: `GOPRIVATE=github.com/stefanoginella/wanonymizer` and a temporary `GOBIN`, so `go install …/cmd/wanonymizer@<pushed commit>` fetches straight from GitHub and adds no entry to the public module proxy or checksum database.
- `.gitattributes`: `* text=auto eol=lf`, and `-text` for `**/testdata/**`. Why: git on the Windows runner checks out with CRLF, and the golden dumps of later milestones compare bytes.
- README: the tool in one paragraph, its status (no release yet), the channels (Homebrew cask, .deb, .rpm, archives, `go install`). The Homebrew line uses the fully qualified name, `brew install --cask stefanoginella/tap/wanonymizer`, because non-official taps need explicit trust by default and short names work only after `brew trust` (docs.brew.sh/Tap-Trust, read 2026-11-27); build checks the current Tap Trust rule. Also: `gh attestation verify <file> --repo stefanoginella/wanonymizer`, the macOS `xattr -dr com.apple.quarantine` command for a direct download, `make tools` and `make check`, and the license. No legal label (`constitution.md`).

## Test design

A `guard` milestone has no AC tests: each AC is proven by the check it names. Throwaway copies come from `git worktree add` in a `mktemp -d` folder, and are removed after the run.

- AC-01: `make check` on the clean tree, on macOS arm64 locally and in the Linux CI job. Cases: exit 0, and the output shows each of the 7 steps. Edge: the placeholder has no test files, so the test step passes with "no test files"; AC-02 proves that the step can fail. Risk: every row of the `testing.md` risk table, whose protections run inside these checks.
- AC-02: one throwaway worktree per seeded defect; `make check` must exit non-zero, and its output must show the failing step. Seeds: an unformatted file (gofmt); `fmt.Printf("%d", "x")` (vet); one finding per linter: errcheck (an unchecked `os.Remove`), gosec (`os.WriteFile` with mode 0o666), errorlint (`err == io.EOF`), nolintlint (a bare `//nolint`), misspell ("recieve" in a comment), forbidigo (`fmt.Println`); an unused `require` in `go.mod` (tidy); a failing test; a test with two goroutines that write one variable, which fails only under `-race`; a type error (build, caught by vet or the build); and for each package of D-08, an import from the entry point, plus one import through a second project package. Edge: a `_test.go` file that imports `net/http` and `os/exec` passes the dependency check. Risk: a check that never fails protects nothing.
- AC-03: `gh pr checks` on the draft PR lists every job of D-07 as passed, for the push run and the pull request run. Edge: the Windows race job (cgo and gcc), and the Go version from `go.mod` rather than the runner's default. No red commit is pushed: AC-02 proves each step fails, and an Actions step fails on a non-zero exit. Risk: a tampered release binary (the workflow checks), and every row that CI runs.
- AC-04: in the release dry run and once locally. Cases: `goreleaser check` exits 0 and prints no "deprecated"; `dist/` holds 6 archives named by target, 2 .deb, 2 .rpm, and the cask, and the cask holds the `xattr -dr com.apple.quarantine` step; `sha256sum --check` passes, and `checksums.txt` has one line per archive and package. Edges: the Windows archives are zip files that hold `wanonymizer.exe`; each archive holds LICENSE and README; no `HOMEBREW_TAP_TOKEN` or release token is set during the run; `gh release list` prints nothing afterwards. Risk: a tampered release binary (P×I 3).
- AC-05: in the release dry run: the .deb in Debian and the .rpm in Fedora, then `wanonymizer --version`; stdout is `wanonymizer <snapshot version>`, the exit code is 0. Once from verify: `go install` at the pushed commit (Approach), then run; it prints a pseudo-version line. Edge: the arm64 packages are not run (Approach). Risk: a release channel that builds but does not install.
- AC-06: actionlint and zizmor pass on both workflows. Read: `release.yml` triggers only on `push` of `v*` tags; the write permissions and `HOMEBREW_TAP_TOKEN` appear only in its release job; `ci.yml` has `permissions: contents: read` and no secrets. Edge: no `pull_request_target` trigger and no untrusted expression in a `run:` step (zizmor). Risk: a tampered release binary.
- AC-07: zizmor with the hash-pin policy passes; in a throwaway worktree, one `uses:` changed to a tag reference makes it fail. Read: each `uses:` ends with a 40-character SHA and a `# v…` comment; `dependabot.yml` lists `github-actions` and `gomod`, both weekly. Risk: a tampered release binary.
- AC-08: diff LICENSE with the SPDX MIT text: only the copyright line differs, and it is `Copyright (c) 2026 <git user.name>`.
